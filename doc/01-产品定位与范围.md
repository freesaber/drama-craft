# 01 产品定位与范围

[English](../en/01-product-scope.md) · [目录](../README.md)

## 目标用户与成果

为使用 Markdown 和本地素材制作短剧的个人创作者提供 Windows 工作台。作品文件夹是工作目录；离开客户端后，剧本和提示词仍可阅读、编辑和版本管理。

## 已实现：P0

项目创建与直接打开、最近项目、上级目录候选作品、文档新建/编辑/保存/另存为、默认纵向故事板、手动源码模式、分镜导航、本地媒体预览、外部改动检测与保存冲突保护。现有文档不会因打开或扫描而被改写。

每个 S 编号对应一张视频单元卡片，可包含多个切镜。左侧只展示当前视频，右侧编辑故事走向、视频提示词、时长、分辨率、Seed 和缩略素材，并可新增、删除、上下移动。无分镜文档显示阅读视图。公共资料与未知内容保留；两种编辑视图共享 Markdown 草稿。

H3 生成链路支持配置服务地址和系统凭据、提交与轮询、结果下载、SQLite 历史和版本切换。客户端实现已由模拟服务测试覆盖；真实服务上传、计费、结果格式及声音效果仍待有效账号验证。

新项目保留“大纲 → 分集文档 → 分镜”的制作组织方式，素材与视频可与文档同目录保存；子目录和外部素材路径也可引用。现有正文没有固定表单要求。

## 已规划

完整制作流程为：导入故事 → 大纲 → 分集剧本 → 分镜及生成片段 → 素材绑定 → 视频生成与选用 → 简单拼接。已有完整剧本时可以跳过大纲。后续素材库支持角色、场景、道具与声音。客户端不要求安装 Codex 或其他创作代理。

一个项目包含多集；当前 S 编号的故事板卡片对应一次视频请求的生成单元，可容纳一个或多个切镜。本次不增加段内切镜的独立结构。后续重生成以该单元为最小单位，历史参数和视频保留。

## 边界

Windows 优先；不自建服务端或 OSS。视频请求只发往用户配置的服务地址。后续只做保留原声的简单拼接，不做多轨时间线、复杂转场或字幕编辑。首帧图片仍由外部工具制作或导入。

## 成功标准

新项目可在自选位置建立；旧项目保持原样接入；中文路径可用；外部编辑与客户端保存发生竞争时不静默覆盖；未知 Markdown 内容可往返保存。具体测试见 [07](07-开发指南与验收.md)。
