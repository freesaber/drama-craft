# 04 Markdown 格式与兼容约定

## 已实现：保留原文

新建分集采用 [08 剧集数据格式 v1](08-剧集数据格式v1.md)。下文的宽松形式属于旧稿兼容规则；不是要求界面随 Markdown 排版变化。剧集视图只展示解析后的数据，角色图和音色绑定展示，其他未知原文从源码入口访问。

任何 UTF-8 `.md` 文档都可以编辑。不要求 frontmatter，不把正文转换成另一套数据库模型。大纲与分镜总表优先显示，随后按数字自然排序显示分集，其他文档最后显示。子目录文档保留相对路径，鼠标悬停显示完整相对路径。

故事板与导航从 Markdown 语法树的顶层标题或独立段落提取 `S001 镜头名`，标题和名称均可省略（编号必需）。镜号支持大小写和不同位数；重复镜号显示诊断并保留各自卡片。普通行必须独占段落；代码块、表格、引用及连续正文中的同形文字不当作分镜。标题分镜在下一个同级/更高级标题或分镜处结束；普通行分镜在下一个分镜或一、二级标题处结束。非分镜内容独立保留原顺序。

```markdown
# 第01集 渡口

本集内容：船工等待归来的旅人。

## S001 点灯

### 首帧生成

出图文件名：`01 首帧_S001.png`。

### 视频生成

视频文件名：`01 S001.mp4`。

| API参数 | 提示词标签 | 上传素材 |
|---|---|---|
| `ref_image_0` | `<Picture 1>` | `01 首帧_S001.png` |

**视频提示词｜duration=5，resolution=768p横**
```

该样例只说明文本组织，不表示已生成素材或已验证服务商参数。新建分集模板包含角色与音色表、素材表、首帧和视频提示词代码块。

## 本地素材

识别 Markdown 图片、链接、引用式链接及行内代码文件名；表格中的这些节点也能识别。普通文本中的裸文件名不做猜测，代码块内部不搜索素材。图片：PNG/JPG/JPEG/WebP/GIF/BMP；音频：MP3/WAV/FLAC/OGG/M4A；视频：MP4/WebM/MOV，实际播放取决于 WebView2 编解码支持。

相对路径从当前文档所在目录解析；含空格的链接可写成 `[参考图](<assets/角色 一.png>)`。Windows 绝对路径原样引用，例如 `Z:/示例素材/角色.png`。缺失文件只显示缺失，不创建假文件，也不修改引用。浏览器内预览失败可用系统应用打开。

远程链接、UNC 网络共享和可执行文件不作为 P0 素材加载。正文预览中的链接和图片保持静态，实际媒体由卡片和素材区域按需加载。每镜引用从自己的区间提取，引用式链接使用全文定义解析；共享定义可在 Markdown 源码中编辑，修改会影响所有引用位置。

## 已实现：故事板编辑与源区间回写

每张卡片在生成区域下方显示“首帧图片”，内含“素材”和“提示词”两个标签页。素材页从本镜首帧生成区的 `GPT附件：图片N＝名称（路径）` 文本中提取图片并横向排列，图片下方只显示图片序号和说明名称；提示词页提供可编辑的首帧图片提示词。视频预览下方仍独立显示本次生成输入。输出文件名及引用路径仍可在 Markdown 源码中编辑。

视频提示词高度按标准双栏布局收紧，使参数与提交区尽量和左侧素材区底部对齐。参考图片和参考音频缩略图分别保持单行横排，数量超出可用宽度时横向滚动。

总表是独立 Markdown 文档，P0 不根据分集自动重写总表。外部编辑器或创作者负责保持重复描述一致。卡片编辑只修改明确定位的源文本区域，两种模式共用草稿；未修改区域保持原样。

字段识别使用现有中文标签：`出图文件名`、`视频文件名`、`首帧图片提示词`、`视频提示词`，以及视频标签中的 `duration`、`resolution`。提示词标签必须紧邻一个完整围栏代码块。故事走向使用 `### 故事走向`（较深分镜标题使用更深层级），首次填写才添加；不存在的提示词和文件名同样按用户操作补入。修改提示词会按需扩展围栏长度。参数只是本地文本，不代表服务商规格已经校验。

重复字段、非标准提示词区、复杂格式的故事走向、无法安全回写的引用等，保留原文并提供源码入口；不猜测内容。六级标题分镜的缺失分区需在源码中处理。缺失素材明确占位，不自动创建文件。

新增镜号采用最大编号加一（至少三位）；删除确认只移除该卡片的完整草稿区间；上下移动只交换相邻分镜，不跨越独立资料，不自动重排镜号。所有改动仍需显式保存，过期草稿补丁被拒绝。
