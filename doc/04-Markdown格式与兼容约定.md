# 04 Markdown 格式与兼容约定

## 文档识别

客户端扫描项目内的 UTF-8 `.md` 文件，并排除隐藏目录、`node_modules`、`target`、`dist` 和符号链接。仅含普通 Markdown 的文件进入阅读视图；存在 Markdown 标题或独立行形式的 `S0001 镜头名` 时，客户端将对应区块识别为故事板卡片。围栏代码中的相同文本不会被识别为分镜。

带 `<!-- drama-craft:episode:v1 -->` 标记的分集按 [剧集数据格式 v1](08-剧集数据格式v1.md) 解析。遇到不支持的版本时，客户端保留正文并只开放源码模式。

## 故事板可编辑内容

卡片可以直接修改镜头标题、故事走向、首帧提示词、视频提示词、时长、分辨率、首帧文件名和视频文件名。客户端不提供新建文档、剧集结构编辑或分镜新增、删除、移动操作；这些结构调整需使用第三方编辑器或 Markdown 源码完成。

所有卡片修改都是针对当前 Markdown 草稿中精确范围的补丁，不会重新序列化整篇文档。字段重复、格式歧义、链接目标无法安全改写或自定义结构无法唯一定位时，卡片显示诊断并提供“定位源码”；用户仍可在源码模式完整编辑。

## 内容保留与素材引用

客户端保留非分镜区块、未知标题、自定义段落、表格、注释和无法识别的字段。素材路径可以写在 Markdown 链接、图片、引用式链接或行内代码中。相对路径以当前文档目录为基准；现有绝对路径保持原样；HTTP(S) 素材不自动加载。

本地预览识别常用图片、音频和视频扩展名。文件不存在或 WebView2 无法解码时会显示状态，用户仍可点击使用系统应用打开。

## 编码、换行与保存

只支持 UTF-8 Markdown，可带 BOM。读取时向编辑器提供 LF 文本；保存时保留已有 BOM，并在原文包含 CRLF 时写回 CRLF。新文件使用无 BOM 的 UTF-8 LF。混合换行文件保存后统一为 CRLF。

保存必须携带读取时的 SHA-256。磁盘文件已改变或被删除时，客户端拒绝覆盖并保留编辑草稿。写入使用同目录临时文件和原子替换；“另存为”禁止覆盖已有文件。
