# 03 项目目录与存储设计

## 当前目录结构

```text
原创作品/
  .drama-craft/project.json
  .drama-craft/generations.sqlite3  # 首次提交生成任务时建立
  剧本大纲.md
  分镜总表.md
  01 第一集.md
  01 首帧_S001.png
  01 S001.mp4
  assets/                 # 可选，支持子目录引用
```

创建项目在选定父目录下创建同名文件夹，已有同名目录时报错；声音源目录必选，角色源目录可选。打开缺少素材库配置的旧项目时，在用户补充目录前不建立项目会话、不写元数据，也不加入最近项目。扫描排除隐藏目录、node_modules、target、dist 和符号链接。

元数据 `project.json` 保存 `id`、`name`、`formatVersion: 1`、`layout: "preserve"` 和 `libraries`。`libraries.characters` 是可选角色目录，`libraries.voices` 是必选声音目录；两者保存用户选择的现有目录，不复制库文件。项目移动后仍保留项目 ID；素材目录移动或在另一台机器打开时，需要重新选择。格式版本不支持、JSON 损坏或已配置目录失效时明确报错，不覆盖。

保存配置前会验证角色目录至少包含一个支持的图片或说明文件、声音目录至少包含一个支持的音频文件。该操作只原子更新 `project.json`，不遍历改写 Markdown，不改提示词，也不在项目内创建素材副本。

最近项目及预览偏好保存在 Tauri 应用数据目录的 `preferences.json` 中；该文件可以包含当前电脑的绝对路径，不随项目分发。复制带元数据的目录会保留同一项目 ID；客户端没有“克隆为新身份”功能。

## 保存语义

读取以原始字节计算 SHA-256，向编辑器提供规范化 LF 文本。保存必须提交原哈希；磁盘内容改变或文件被删除时拒绝覆盖。原 UTF-8 BOM 和 CRLF 风格保留，新文件使用无 BOM 的 UTF-8 LF。混合换行文件保存时若含 CRLF 则统一为 CRLF。

替换使用同目录临时文件，写入并同步后原子替换目标；新建使用禁止覆盖的持久化操作。该流程保护普通编辑器冲突与部分写入，不提供跨进程文件系统 compare-and-swap，也不承诺断电后的完整目录持久化。只读属性会在替换前检查。历史视频裁切同样覆盖原文件名，不另存副本，也不改写 Markdown。

外部修改在手动刷新或恢复窗口焦点时检查。编辑器干净时读取新版本；有未保存内容时保留编辑器并提示冲突。当前客户端不使用后台文件监听，也不自动保存。

## SQLite 的定位

| 数据               | 权威存储    | 是否可重建     |
| ------------------ | ----------- | -------------- |
| 剧本、提示词、说明 | Markdown    | 不可丢弃       |
| 素材与视频         | 本地文件    | 不可丢弃       |
| 项目设置           | 项目 JSON   | 项目标识应保留 |
| 生成任务与版本索引 | 项目 SQLite | 不可当缓存丢弃 |
| 文档扫描结果       | 运行时内存  | 可从文件重建   |

`generations.sqlite3` 按需建立，保存远端任务 ID、提示词、参数、输入引用、状态、结果 URL 和本地文件索引；并包含批量任务主表 `batch_jobs` 与明细表 `batch_job_items`。当前选中的视频仍由 Markdown 的“视频文件名”决定；切换历史版本会走正文哈希冲突检查。数据库不保存正文和凭据，也不复制素材快照。

复制整个项目不会携带外部角色和声音库；当前客户端不提供素材归集、完整备份或在线任务恢复。
