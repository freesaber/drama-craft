# 09 项目工作流程

## 整体架构

DramaCraft 是一个 Windows 桌面工作台（Tauri 2），不包含后端服务。它的核心角色是**项目管理者和结果展示器**，不是内容生成器。短剧的剧本、提示词和素材由外部 AI agent 生成，客户端负责：

1. 创建并初始化项目结构
2. 打开并解析外部 agent 生成的分集剧本
3. 以故事板形式展示、编辑和管理分镜
4. 管理视频 API 配置、提交生成任务、下载结果

## 完整工作流程

### 阶段一：客户端创建项目

用户在 DramaCraft 中点击"创建项目"，选择父目录、项目名称和声音目录。客户端自动生成以下文件：

```
项目名/
├── .drama-craft/
│   └── project.json       # 项目元数据（ID、素材库路径）
├── AGENTS.md              # 外部 AI agent 的创作指导（格式规范、流程、音色列表）
├── assets.json            # 作品级资产检索索引（不保存文件名和提示词）
├── 剧本大纲.md            # 故事大纲模板
└── 全剧人物与对白.md      # 全剧人物登记和逐集完整对白模板
```

其中 `AGENTS.md` 是关键文件——它包含完整的创作引导流程和 v1 格式规范，供外部 AI agent 读取并遵循。

`assets.json` 初始为 `{"schemaVersion":1,"assets":[]}`。登记后每条资产包含 `id`、`type`、`name`、`aliases`、`keywords`、`firstDocument`；状态变体再填 `baseId`。`id` 与首现集表格中的四位编号相同，例如角色 `C0001`、场景 `A0001`。`type` 取 `character`、`scene`、`prop`、`crowd`、`variant`；`firstDocument` 是相对项目根目录的首现集 Markdown 路径。索引不复制素材文件名、音色路径或完整提示词；命中后从首现集读取。每镜首帧和生成视频不登记。

新建项目的视频提示词示例采用 H3 Ref2VA 标签语义的简化格式，标签定义与非台词正文使用英文：`<Picture N>` 指上传图片，`<Subject N>` 定义从参考图中追踪的可见主体，`(Sx)` 按本条视频首次发声顺序编号，`<Audio N>` 绑定发声者，实际台词用 `<d>...</d>` 包裹。主体、音频、发声者和项目镜号分别编号；纯系统声或旁白没有可见主体时使用稳定名称与 `(Sx)`，不虚构 Subject。Subject 不产生额外上传参数，客户端继续按原素材映射表提交。首帧 `<Picture 1>` 作为具体画面锚点单独定义；仅提供主体外观的参考图只在英文 `<Subject N>` 定义中引用，不另写 Picture 定义行。英文视频正文使用 Subject 标签，中文角色名留在映射与剧本中，中文对白留在 `<d>[Chinese] ...</d>` 中，原词不翻译，完整句在 `</d>` 前按句型以英文 `.`, `?`, `!` 收尾。该模板仍非官方六节完整重写格式；它表达引用关系，不保证音色或台词生成效果。规则依据 [官方 Ref2VA 指南](https://raw.githubusercontent.com/MiniMax-AI/MiniMax-H3/main/skills/h3-prompt-writing/references/ref-en.txt)。模板更新只作用于之后创建的项目，不自动覆盖已有项目的 AGENTS.md。

### 阶段二：外部 AI agent 生成内容

用户在任意 AI 工具（DeepSeek、Cursor、Claude、Codex 等）中打开项目目录。AI agent 读取 `AGENTS.md`，按照其中的流程引导用户完成创作：

1. 选择题材和风格
2. 确认时长与集数的硬性约束、是否使用旁白；选择不使用时，全剧不创建旁白角色、旁白声音安排或旁白提示词
3. 构思并写入故事大纲（`剧本大纲.md`）
4. 大纲确认后，先完成 `全剧人物与对白.md`：登记全部人物，先写并保留可连读的完整对白正文，再逐字分配到S镜号；每个S镜号对应一条1—15秒的视频请求，逐句估算发声和动作容量，超时移动分界或增加单元，不压缩台词；在必要动作中核对前后状态，再检查主要因果与选择
5. 全剧对白稿完成后，先写第0001集分镜供用户检查；文稿确认或已授权连续完成后按集顺序继续，不要求生成样片。每集写前读取大纲、全剧人物与对白、上一集和 `assets.json`，复用时查首现集；写完立即登记本集新增角色和可复用素材，首帧不登记
6. 全剧验收各集分镜、角色与素材引用后交付

`全剧人物与对白.md` 是普通 Markdown 创作稿，客户端以阅读视图展示，不添加剧集 v1 标记或新增解析字段。对白稿先规划 S 镜号与预计时长，正式分镜沿用；调整镜号或台词时同步两处。地点或时间的「场景」可以出现在动作描述中，不作为对白分组或视频生成单位。尚未确定的角色图或音色写待生成、待确认。对白稿阶段逐镜估算容量，正式分镜后逐镜验收，不能用整集平均字数替代。

模板以自然完整的对白为先，不设置逐镜最低字数，不因少字补词或因15秒上限缩句。按普通约4字/秒估算，另计换气、换人、停顿、不可重叠动作及约10%余量。逐次发言和整镜都须容得下，超时优先在换人、整句、完整分句或自然换气处分到更多S单元；保留台词原词、顺序和故事结果。参考单集时长按授权延长，用户明确硬性上限的冲突如实记录。技术拆分后同步对白分配表、声音安排、镜号、文件与映射引用；已有生成记录不静默改号。

逐镜记录时长、实际发音字数、发言次数、发声区间（正式分镜阶段）、估算耗时、必要动作、余量与判定；必要低对白或静默说明剧情作用即可，不额外要求豁免确认。时长注明文本估算、未实测，不把试读或样片设为交付前置条件。这些是创作代理的检查要求，客户端不会自动判断对白自然度或容量。

### 手动使用上一镜尾帧

同地点、连续时间、同机位或连续运镜的相邻片段，可将后镜现有“首帧图片提示词”的text围栏固定写为“上一镜尾帧”，不另加字段或承接表，不在这五个字后补风格和画面描述。第一镜、换场、跳时、反打或重构图仍使用正常生图提示词。人物、道具和动作的前后衔接写在故事走向与视频动作中。

用户生成上一镜视频后，手动取得尾帧并上传为本镜首帧。出图文件名与视频映射仍使用本镜自己的PNG；后镜从上传的画面继续，保留自己的完整台词、角色参考及音色。这五个字只是人工操作提示，不提交给生图模型，不要求客户端自动提帧或调度。尾帧不传递音频，拆分仍须避开词中，保持语气和环境声一致。

每集 `.md` 文件遵循 [剧集数据格式 v1](08-剧集数据格式v1.md)，包含角色绑定表、素材表、声音安排表、新增素材生成提示词和完整分镜。

写分镜前，agent 先写连续故事底稿，检查单集目标、阻碍、选择和结果，再把必要信息对应到具体镜号的画面或台词。交付前遮住大纲、梗概、镜头标题与故事走向，仅凭成片中能看到、听到的内容检查理解是否连贯。底稿和信息对应可留在工作笔记中，不增加 v1 必填字段或逐集确认步骤。

### 阶段三：客户端打开并展示

用户回到 DramaCraft 客户端，打开项目。客户端解析每集 `.md` 文件，提取：

- **角色数据**：ID、名称、角色图、音色绑定、生成提示词；每镜出场关系只写在分镜的 `角色：` 字段
- **素材数据**：场景/道具引用、文件路径、生成提示词
- **台词数据**：分镜对白、角色名称
- **分镜卡片**：故事走向、首帧/视频提示词、参数、文件引用

解析出的数据以纵向故事板展示。用户可以在卡片中编辑提示词和参数，查看/预览本地素材，或切换到 Markdown 源码模式编辑。

### 阶段四：生成与迭代

配置视频 API 后，用户在故事板卡片中核对参数并点击"生成视频"。客户端提交任务、轮询进度、自动下载并归档版本。

## 客户端解析与外部 agent 生成的衔接

客户端解析器严格按照 v1 格式规范工作。外部 AI agent 生成的内容必须满足以下关键约束才能被正确解析：

### 已知的外部 agent 常见偏差

由于外部 AI agent 并不总是严格遵循指令，以下是已知的常见偏差和客户端的应对。**所有项目 `.md`（大纲、全剧人物与对白、各集提示词）都适用「标准 Markdown」约束，不只大纲。**

| 偏差 | 示例 | 客户端处理 |
|---|---|---|
| 生成提示词标题使用前缀格式 | `### 角色参考图：林逸` 而非 `### 林逸` | 解析器同时匹配 `### 名称`、`### 名称参考图`、`### 前缀：名称` |
| 并行子 agent 互不阅读就批量写各集 | 第0005集已有 `0005 素材_王宫大殿.png`，后续集却写成 `0003 素材_王宫大殿.png`；某场景只在素材表登记，却未写生成提示词 | 不自动修正；AGENTS 要求一次完成一集，登记资产后才写下一集，并做全剧验收 |
| 角色绑定表误加出场镜号列 | 角色绑定表多写了每镜已经维护的出场关系 | 四列表头固定为 ID、名称、角色图、音色文件；每镜通过 `角色：` 字段声明出场角色 |
| 表格列使用对齐语法 | `|:---:|` 而非 `|---|` | 正常解析，不要求对齐格式 |
| 路径写成裸文本，未包反引号 | `F:/voices/a.mp3` 而非 `` `F:/voices/a.mp3` `` | 单元格整体可作为媒体路径回退解析；仍建议写行内代码 |
| 非法 Markdown 表格 | 分隔行写成 `|::---|`，或多行用 `||` 粘在一起 | 预览整表坍成段落；须靠 AGENTS 约束生成标准 GFM |
| 分镜区标题带冒号 | `### 故事走向：` 而非 `### 故事走向` | 客户端接受可选尾部冒号；仍建议写无冒号标准标题 |
| 视频时间线写小说说明 | 「东西还在，它真的没有消失」没有发声主体；只删破折号、留下原句 | 客户端原样提交；模型可能念成台词。须靠 AGENTS 约束：只写可拍画面，或改成有主体的对白/内心独白 |
| 关键因果只写在故事走向 | 说明里解释行动理由，视频只剩皱眉与转身 | 不自动识别；靠 AGENTS 要求必要信息对应具体镜号，进行脱离说明的视听连读验收 |
| 固定镜数导致信息拥挤或重复 | 先把每镜定成相同时长，再塞入多项任务或重复反应 | 不自动判断；靠 AGENTS 先确立单集核心任务，再按动作、对白与阅读时间分配镜头 |
| 时间和跨集条件不一致 | 混用不同事件的时间间隔，先获得成果再补取得条件 | 不自动推理；靠 AGENTS 建立时间与状态基准，核对期限、前提与跨集结果 |
| 群像与个人 Subject 身份重叠 | 同一参考中先定义整群，再把某个成员定义为另一个 Subject，用成员关系句解释人数 | 不自动拆图；AGENTS 只允许整体引用背景群像，成员禁止被单独指认；独立人物各有个人图与唯一 Subject，同一人不在群像和个人引用中重复出现 |
| 视频提示词夹带项目 ID | 在 Subject 定义或括号备注中写角色、素材或项目镜号 | 客户端当前原样提交；AGENTS 要求整个视频 text 围栏不出现项目编号，只保留本条请求的 Picture、Subject、Audio、Video、Shot 与发声者标签，项目查表关系留在围栏外 |

### AGENTS.md 模板的职责

`AGENTS.md` 模板（由 `storage.rs` 中的 `agents_md()` 函数生成）承担以下职责：

1. **创作引导**：从题材选择到分集生成的完整流程
2. **格式规范**：v1 剧集格式的完整说明和示例；角色表固定四列，出场关系只写在每镜的 `角色：` 字段
3. **素材库配置**：声音目录路径和可用音色快照
4. **一致性约束**：角色 ID 跨集一致；每镜角色关系只维护在 `角色：` 字段；跨集素材文件名逐字相同；首现集必须有生成提示词。群像只能作为整体背景群众使用，禁止单独引用、点名、按位置/衣着指认、安排个人行为或发声、定义成员 Subject；需要个人身份的人物各自作为独立角色，个人图由角色绑定表管理，不在素材表重复登记，即使同框也不与包含同一人物的群像混用。组合道具图同样只整体使用，单件使用时须有独立记录和单件图。逐镜只引用实际可见且有参考价值的最少素材
5. **首帧与视频提示词内容、风格及旁白约束**：独立生图的首帧图片提示词在画幅比后显式写出用户确认的完整核心风格词，不能只靠附件暗示；每镜视频提示词也带入同一风格；尾帧承接镜的首帧提示词只写“上一镜尾帧”，画面风格从上传的尾帧继承。记录并贯彻用户对旁白的选择，选择不使用时不创建 `N0001`、旁白声音安排、旁白音色引用或旁白段落；只写可拍画面与有发声主体的台词，禁止小说式说明；视频正文用英文 `From X to Y seconds, ...` 表示时间段，不用破折号串联动作或代替正常标点，改用自然英文完整句（新建项目的 AGENTS.md 必须自包含这些规则，不能依赖仓库或其他历史上下文）
6. **生成节奏与验收**：大纲确认后先完成全剧人物与对白，再写第0001集分镜文稿供检查，不以生成样片为前提；确认或已有连续授权后每次只完成一集正式分镜，登记本集首现资产并核对复用后才写下一集。已授权连续完成时不重复请求确认，但不跳过对白稿。每集写前读取上一集以承接剧情，并查询 `assets.json` 及命中资产的首现集以核对文件名。不同集不并行写稿；全部写完后做全剧验收
7. **叙事清晰与单集容量**：先写连续故事再拆镜，一集围绕一个核心任务；区分悬念与理解所需的基本信息，关键因果必须进入画面或台词。时间信息使用统一事件基准，换场承接目标，结果具备前提。超载时先删重复、延后非必要信息、收窄任务，再考虑调整时长或集数；用户硬性规格优先
8. **视频编号与后续优化约束**：视频提示词整个 text 围栏禁止包含项目角色、素材、旁白与镜号等内部编号；允许本条请求的引用标签、`[Shot N]` 和发声者 `(Sx)`，查表关系留在围栏外。创作及后续角色定义、素材完整性和引用链检查都遵守同一素材身份规则，不因旧图、旧登记或保持路径的要求而继续从群像提取个人；拆分所需素材未生成时列为待生成，不用成员关系句补救

自检与验收条目使用普通 Markdown 圆点列表（`- 条目`），不使用任务复选框（`- [ ] 条目`）。

这些是给外部创作 agent 的写作与审稿规则，不是客户端新增的剧情自动检测功能，也不保证外部模型始终遵守。模板由客户端编译打包，使用更新后的客户端创建项目才会写入新规则；已有项目的 AGENTS.md 不会自动覆盖。

模板质量会影响外部 agent 的生成质量。当发现外部 agent 系统性地产生某类错误时，应优先改进模板指导，其次增强客户端解析的容错性。

### 为何不能只靠「禁止子 agent」

集内错误（如角色字段漏写）一集一集写也会出现。跨集错误（改文件名前缀、首现集漏写生成提示词）会在批量或并行写稿时放大。因此每集完成后先更新根目录资产索引，再开始下一集；全部完成后仍做独立的全剧验收。
